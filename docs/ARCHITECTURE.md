# 架构说明

## 当前入口：模拟驱动的《城破前夜》（src/sim/）

`src/main.tsx` 当前加载 `src/sim/SimApp.tsx`。这是一个信念传播模拟器：

```text
createSim(seed)
  → 选择开局誓愿（choose-vow，只影响终局追问，不暗改数值）
  → 白天命令（applyCommand）：move / observe / probe / collect / forge / alter / destroy / dispatch / rest
  → 第四个时辰花完自动入夜（runNightTick）：
      时局大钟 → 文书在途（带信人私心：转卖/加戏/昧下 → 送达验看 → 信念更新）
      → 流言衰减一跳（每夜每人上限）→ 人物自主行动（信念过阈，每局一次）
  → confirm-report 读晨报进新的一天
  → 三月十八夜后 settleNode：九根支撑柱确定性清账 → 三撬点分别结算
      （零倒柱 = 0 且不掷骰；玩家因果已抵达则记“有过波澜”，否则记“未触碰”；部分倒柱 = 10 + 权重，夹 10–90；三柱全倒 = 100 且不掷骰；确定性人物行动可直接保证）
      → 七类正常结果族优先级级联 → buildChronicle 三层编年史
```

核心机制约定：

- `SimState` 是唯一权威状态；React 组件只提交 `PlayerCommand`。
- 信念四档（未闻/存疑/半信/笃信），`applyBelief` 是唯一写入口，强制记因果账（audit）；单次更新至多 ±2 档。
- 识破判定沿旧引擎胜算公式形状：`35 + 精明×15 − 质量×15 − 想信程度×10`，夹 10–90；「想信程度」= 断言命中验看者的欲望或恐惧（宁可信其有）。骰值入账，终局全部公开。
- 嫌疑 0–10，阈值 4 盘查 / 7 搜查（违禁部件按公开骰没收）/ 10 缉拿；被处决同样生成编年史（失败即内容）。
- 玩家知识层与模拟真实状态分离：人物册只显示探得的底细、行踪与信念快照；夜里只播报 `visibleToPlayer` 的账目。
- `previewCommand()` 只把既有合法命令翻成行动前的定性信息：时辰、银两、文书成色、嫌疑、已探得的带信人偏向、收信人验看风险与不可逆承诺。未探底细时只提示“尚未摸清”；它不掷骰、不推进种子，也不泄露精确暗骰。
- 刻工技艺 `craft` 初始为 1；第一张文书仍按原技艺结算，完成后升至 2，后续文书成色额外抬一档。成长不增加随机抽取，预览与实际锻造共用 `forgeGrade()`。
- 随机全部出自存档内 LCG（`next = state×1664525 + 1013904223 mod 2^32`，复制自旧引擎）；规则层禁 `Math.random()` 与时间戳；文书与账目用确定性自增序号。
- 存档 `what-if-history.sim.v7`：`validateSimState` 先做结构和命令白名单校验，再从 `seed + commands` 全量重放并逐字节比对整态 JSON——伪造信念、嫌疑、结局、原型键或命令序列的档一律拒收。v6 键原地保留但不迁移，因为节点审计与验看文字已经改变，不能用新规则伪装重放旧局。总命令上限 1000；免费移动达到 400 次后仍保留耗时动作，不形成死档。自动保存、清除、抄出和读入都返回显式结果；读入文件先重放核对，失败不覆盖当前状态。
- 史鉴 `what-if-history.codex.v2` 跨局收藏：因果连线（人物×断言→行动）、带史料来源的编年史（按 seed+结果族去重，上限 50）、人物档案；合并函数纯函数化，时间戳由存储层注入。
- 七个正常结果族穷尽三个撬点的八种真假组合；`水遁` 明确要求门未撬动而春生获救，名册结果不改变题签。不可达的旧 `luan-ye` 兜底已退出活动结果表，只为早期史鉴记录保留显示兼容。
- 声音由 Web Audio 在浏览器本地实时合成，噪声使用固定 LCG，不调用 `Math.random()`；静音与音量单独保存在 `what-if-history.audio.v1`，不参与规则或回放。终局声音按开局誓愿对应的撬点是否兑现区分成功与失败；同种子重走重新调用 `createSim(state.seed)`，不改变骰序。
- 内容层四表分离（人物/断言/文书型制/支撑柱……），`validateContent()` 是可执行的内容规约：引用完整性、史实标注硬约束（真值断言必须给来源；纯架空引用 counterfactual 特例，不伪造史源；架空说明前缀）、可玩性护栏（每撬点 2–4 根柱且分属≥2 人；每条撬点断言至少有一种型制可承载；每种要件全城至少一处可采；行踪表无缺格；关系网连通），并穷举结果族可达性，拒绝遗漏组合或不可达族。

`npm test` 当前有 28 个测试文件、137 项：覆盖确定性重放（同种子同命令终态含因果账全等）、序列化往返、严格命令校验、物件不重生、纸张次数、技艺成长、同夜传闻不二跳、内容 linter、传播不变量、嫌疑阈值、八类结果的固定合法命令见证与穷举映射、起始资源路线、三柱全倒确定兑现、零倒柱时“未触碰 / 有过波澜”的因果区分、按文书型制验看、行动预览不推进随机状态且不泄露未探底细、游戏内新手引导与三种誓愿首步、首页备案与权利声明、模态焦点与工具弹层、夜报可见口径与危险优先级、人物命运、史鉴进度、同种子重走入口、终局声效、存档失败、篡改与覆盖边界，以及 200 种子随机漫游 fuzz（无死局、因果账可解引用）。

## 归档一：人物驱动的三回合竖切（src/story/，无界面入口）

上一版竖切，代码与测试完整保留，无界面入口。其纯函数叙事状态机：

```text
createStory(seed)
  → 人物冲突 + 可观察物件
  → inspectClue(state, clueId)：检查现场物件
  → resolveStoryChoice(state, choiceId)：一次不可兼得的行动
  → 人物反应 + 具体后果 + 新债务
  → advanceStory(state)：下一回先回收旧选择
  → 第三回生成小结局与历史偏转
```

`StoryState` 是新模式的唯一权威状态，保存回合、阶段、观察、人物信任、旗标、未结与已结债务、选择和结局。场景与回合后果由状态通过纯函数派生；最终结局文本作为完成时快照随存档保存。

- 存档版本为 `saveVersion: 3`，使用 `what-if-history.story.v3`。
- 旧 v2 策略存档保留但不迁移，新旧模式不共享状态结构。
- 当前竖切没有随机判定；种子与随机状态仍随存档保留，为后续规则扩展留下可复现边界。相同初始状态、观察和选择必须产生完全相同的历史。
- React 只提交观察和选择，不直接修改人物、债务或结局。

玩家至少观察两件物品后才能行动；每个选项都要求一件特定证据。第三回的部分行动会被此前形成的人物信任封锁。`validateStoryState()` 会校验观察字段，并从种子重放选择以核对派生状态，拒绝伪造旗标、债务、人物关系、阶段或结局的存档。

sim 引擎从这里回收了三样东西：先看清再动手的观察门控、重放防篡改校验、六个人物的设定与文本。

## 归档二：旧版十二回合引擎（src/game/，无界面入口）

sim 引擎从这里回收了四样东西：LCG 种子随机、胜算公式形状、结局优先级级联、内容 linter 纪律。

### 设计边界

游戏是纯前端单页应用。React 负责展示和收集 `TurnPlan`，所有规则由 `src/game/engine.ts` 中的纯函数执行。界面不得直接修改国势、资源、人物关系或随机状态。

没有服务器、数据库或运行时内容生成。事件表、人物和来源均随构建产物发布，因此同一版本中的同一种子可以完全复现。

### 单局状态机

```text
createGame(seed)
  → 准备回合：主线事件 + 从本幕事件池抽取一个未见事件
  → 同时展示两份奏案：在 2 点诏令内选择政策并分配不同执行者
  → 整回合落印：执行已部署政策，未处理奏案触发一次失控后果
  → 回合推进：结算到期命令、更新国势、抽取下一回合
  → 第十二回合结束：buildEnding(state)
```

`GameState` 是唯一权威状态，包含：

- `turn`、`act`、当前两份奏案和本局已见动态事件。
- 五项 `metrics` 与内帑、驿骑两项 `resources`。
- 人物存亡、关系、剧情旗标和等待结算的命令。
- 随机数内部状态、玩家决策、未处理奏案和可公开回报。
- `saveVersion: 2`。v1 进行中对局明确不迁移，独立保存的结局史鉴继续沿用。

### 御前部署

每回合有 2 点诏令。每项政策在部署元数据中明确标为 1 点或 2 点，数值同时考虑协调难度、时效和资源规模，不由执行判定自动推导。玩家至少要下达一道诏令，未获得诏令的奏案不会积压，而是在本回合触发一次标记为“架空推演”的失控效果。每个动态事件都保留一个不耗资源的一诏方案，确保资源耗尽时仍能推进回合。

所有诏令都必须指定执行者，同一人物每回合只能承接一道。确定性政策中的执行者用于限制可行部署组合；含 `check` 的政策还会把人物能力和关系计入到期时的胜算。

React 只维护尚未落印的部署草稿。`validateTurnPlan(state, plan)` 与 `resolveTurn(state, plan)` 负责全部合法性校验、资源扣除、效果应用、待结算命令和回合推进，组件不得直接修改 `GameState`。

### 决策与延迟执行

政策可以包含三类后果：

1. `cost`：落印时扣除的明确资源；不足时不能选择。
2. `immediate`：立即发生的确定性状态变化。
3. `check`：延迟 1–2 回合的执行判定，保存事件、政策和执行者引用。

判定到期时才使用当时国势计算胜算：

```text
胜算 = 基础胜算
     + Σ((国势 - 50) × 对应权重)
     + (执行者能力 - 10)
     + 人物关系 × 0.2
```

结果限制在 10%–90%。游戏过程只显示四档风险，结局页公开精确胜算与掷值。

随机数使用存档内的 32 位线性同余状态：

```text
next = (state × 1664525 + 1013904223) mod 2³²
```

禁止在规则代码中使用 `Math.random()`。新局种子可由当前时间产生，但之后所有抽取和判定都只依赖 `rngState`。

### 内容模型

每个 `EventDefinition` 必须包含：

- 唯一事件 ID、所属幕、时间、分类、奏报和策略背景。
- 一个来源 ID，以及明确区分史实和架空部分的 `boundary`。
- 恰好三个 `ChoiceDefinition`；选择不能只换措辞而没有不同代价。

每个事件还必须在 `src/game/strategy.ts` 的 `EVENT_STRATEGY` 中拥有一条部署元数据：地图区域、三个方案各自的诏令成本、默认可用执行者，以及明确标注为架空推演的专属失控文本和效果。方案自身的 `actorIds` 可以进一步收窄执行者范围。

`validateContent()` 在测试中检查事件 ID、选择 ID、人物引用、部署元数据、至少一个一诏方案、延迟和每幕事件池容量。新增事件时必须保持十二个主线事件，并让每幕至少有五个动态事件。

### 结局

`buildEnding()` 先依据国势和关键制度旗标选择六类国运之一，再拼接三段长期叙事：民间承受、制度遗产、北方关系。结局优先级避免低粮但已有海上退路的局面被误判为普通朝局崩溃。

结局不是线性总分：例如高合法性但低兵权会进入“军镇挟天子”，而不是用平均值抵消指挥链崩坏。

### 存档与隐私

- `localStorage` 保存一个 `what-if-history.autosave.v2` 自动存档。
- 完成的结局写入 `what-if-history.annals.v1`，相同种子和结局不重复，最多保留 20 条。
- 所有数据仅留在当前浏览器，不上传任何信息。
- 每次落印后立即保存，包括随机状态和待结算命令。

### 验证

`npm test` 覆盖内容完整性、完整十二回合、同种子复现、序列化复现、资源与执行者校验、六类结局和损坏存档。

`npm run build` 同时执行 TypeScript 项目检查和 Vite 生产构建。界面变动还应在 1440×900 与 390×844 视口各完成一次真实浏览器检查。
